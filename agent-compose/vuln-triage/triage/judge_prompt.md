# 任务：镜像漏洞适用性研判

下面的"证据"是脚本从漏洞快照里查好的，包含若干个有漏洞的软件包。对每个包判断：在**当前环境**下，它有没有被用到。
只能根据给出的证据下结论，不许猜测，不许使用证据之外的信息。

## 证据字段说明

- `usage`：采集那一刻的运行时证据。
  - `not_observed`：镜像有容器在运行，但采集时没看到这个包被使用。**这不等于用不到**：偶尔才运行的程序、按需调用的工具（例如服务导入时才调用的 npm、git）也会是这个状态。
  - `no_runtime_evidence`：镜像没有容器在运行，没有运行时证据。
  - `not_tracked`：node/python 依赖这类包，没法用进程和库来对应。
- `files`：镜像里这个包装了哪些文件（来自镜像内的 dpkg 文件清单）。`executables` 是可执行程序，`sharedLibs` 是共享库，`scripts` 是脚本，`counts` 是各类文件数；`note` 非空表示没有文件清单。
- `image_entrypoint` / `image_cmd`：镜像的启动命令。
- `vulns`：按严重程度排序的漏洞，前几个带 `description`（漏洞描述，可能被截断），用来看漏洞要在什么条件下才能被触发。

## 三种结论（必须三选一）

- **正在使用**：证据表明这个包会被运行。例如它就是启动命令直接运行的程序。
- **用不到**：证据表明在当前环境下它不会被运行。必须同时写出：①依据的具体证据；②结论成立的前提条件（条件一变结论就作废）。可接受的依据例如：漏洞所在的程序或库**不在**这个包的 `files` 里；漏洞只在某个功能/组件存在时才能触发，而证据显示这个组件不存在。
- **证据不足**：上面两种都证明不了。**拿不准时一律选这个。**
- **禁止**的推理："采集时没有进程在用它，所以用不到"。`not_observed` 和 `no_runtime_evidence` 本身不能作为"用不到"的依据。

## 输出

只输出一个 JSON 对象，不要有代码块标记或任何其他文字：
{"batch":"<批次名>","results":[
  {"image":"<镜像短ID>","package":"<包名>","verdict":"正在使用|用不到|证据不足",
   "reason":"一句话理由，写清依据的是哪条证据",
   "evidence":["你用到的证据原文要点，每条注明来自哪个字段，例如 files.executables、image_cmd、vulns[CVE-xxx].description"],
   "conditions":["结论成立的前提条件；判为用不到时至少一条"],
   "missing_evidence":[{"type":"file_content|file_exists|setuid|listening_ports|process_args|other","target":"要查的对象","why":"有了它能把结论改成什么"}]}
]}
- 每个输入的包必须有且只有一条结果，`image` 和 `package` 必须和输入完全一致，顺序也一致。
- 判为证据不足时，在 `missing_evidence` 里写出缺哪项证据就能下结论；其他结论可以留空列表。
